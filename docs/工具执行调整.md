# 工具经验如何实际改变执行

本次在已有绘图路由之外接入发送、语音、草图、页面流程与约定。规则由真实执行结果产生，程序只执行固定的恢复分支，不执行反思文字里的任意指令。

| 场景 | 下一次真正发生的变化 |
| --- | --- |
| GPT-SoVITS 断开、超时、502/503/504 或缺少配置/依赖 | 合成新一句话时先采用现有 Edge TTS 备用；30 分钟后重新探测，配置或参考音频改变时重新评估 |
| 草图解释器失败 | 尝试系统 Python；下一次条件相同时优先走可用备用。两边都失败就暂停同条件重复，不生成占位图冒充成功 |
| 图片发送、语音发送失败 | 读取执行经验，条件未变时暂停原样重试。结果不明时不通过重新合成、更换临时文件名或改发文字来变相重发 |
| 多条消息只成功一部分 | 每个气泡有独立的持久发送意图与回执，整批重试复用已成功的气泡，只处理未成功部分；同批次明确要求的两个相同气泡按位置区分 |
| 网关超时、断开、HTTP 5xx、返回非 JSON、缺少消息 ID、异步 retcode=1 | 状态保持待核对；只查本机可验证回执，不把没收到响应当成明确未发送，也不伪造成功 |
| 页面/约定因缺少证据或步骤不符失败 | 在鉴权之后重读真实状态、文件哈希、来源消息及回执；输入和条件都未变则不再调用写入函数，补齐证据或纠正输入后才恢复 |

## 状态和时效

- 新文件 `state/delivery-operations.json` 只保存目标、意图/请求哈希、时间、状态和实际消息 ID，不保存音频字节、模型令牌或待发送正文。
- 发送前先原子保存 pending；进程退出后不会把它当作一条新消息。若发送回执已写入而结果状态尚未落盘，下次按操作 ID、目标与请求哈希核对后恢复。
- 成功发送在相同用户来信意图中做 **2 分钟**去重；明确拒绝做 **30 秒**退避。进行中或结果不明的同一请求不会随退避到期自动重发；即使又收到新来信，也须先核对这条旧请求，不能据此推断旧消息没发出去。
- 语音/草图和状态写入规则通常为 30 分钟。备用成功不延长主方法失败的有效期；备用也失败会暂停两条坏路。只重读状态和暂停的决定单独记录，不计为新的实际工具失败，不不断延长失败时间。
- 普通经验可通过原有操作台启停；停用经验不会取消发送结果不明时的去重保护。无法核对的发送可以继续保持受阻，不承诺网络没有幂等键时能自动解决所有不确定交付。

`qq_learning` 能看到每次实际换备用、复用回执、暂停写入的依据、动作与结果。纯只读的状态查询不受这些写入退避限制。目标白名单、会话鉴权、频率限制和完成证据规则仍在原位置执行，不能以“学会了”为理由绕过。

## 验证

单元测试覆盖换路、不同文本共享服务失败经验、证据变化、规则到期、未知发送不随配置变化重做、并发、部分成功重试、崩溃后用真实回执恢复、异步回执与状态文件损坏。

集成测试使用真实 bridge/MCP 和本机假 QQ。语音另用测试专属的假 503 引擎与 Python 标准库音频生成器，验证新进程下一句不会再调用坏引擎，发送断开后不改发文字；这不属于真实云语音质量验证，也没有给真实 QQ 发测试消息。

运行目录部署后验证项目和约定的“失败→原样重试暂停”，并生成一张仅在本机保存的草图。原人格、长期记忆、作品、配置、密钥及项目进度均做前后校验，经验记录只追加新证据。
