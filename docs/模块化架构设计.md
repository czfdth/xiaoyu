# 小鱼 · 模块化集成架构

> 目标：一个可在 Windows 安装的程序，核心很小，重的东西可选。
> 原则：**没装某个引擎，就优雅降级，不是报错。**

---

## 一、总结构

```
┌─────────────────────────────────────────┐
│  小鱼（核心安装包，约 40 MB）              │
│                                          │
│  ┌────────────────────────────────┐     │
│  │ SnowLuma（QQ 网关，改造后）      │     │
│  │  ├ 登录 / 收发 / 媒体            │     │
│  │  └ 插件宿主 ← bridge 作为插件    │     │
│  └────────────────────────────────┘     │
│                                          │
│  ┌────────────────────────────────┐     │
│  │ 小鱼管家（托盘 + 面板）           │     │
│  │  · 状态 / 启停 / 日志            │     │
│  │  · 日记 / 回忆录 / 梦            │     │
│  │  · 人格卡编辑                    │     │
│  │  · 能力开关（语音/画图/唱歌）      │     │
│  └────────────────────────────────┘     │
└─────────────────────────────────────────┘
              │ 按需调用
     ┌────────┼────────┬──────────┐
     ▼        ▼        ▼          ▼
  GPT-SoVITS ComfyUI   RVC      其他
  （外置）   +SD1.5   （可选）   （插件）
   6 GB     12 GB     3 GB
```

**核心 40 MB 装完就能聊天。** 声音、画图、唱歌都是后装的模块。

---

## 二、模块与降级

| 模块 | 检测方式 | 装了 | 没装 |
|---|---|---|---|
| **语音** | 9880 端口能连 | `qq_say` 可用 | 只发文字，工具不注册 |
| **画图** | 8188 端口能连 | `qq_draw` 可用 | 不能画，会说"今天画不了" |
| **唱歌** | 模型文件存在 | `qq_sing` 可用 | 不能唱 |
| **联网** | 永远可用 | 搜索/读网页 | — |
| **电脑操作** | 默认关，需手动开 | 9 个工具 | 不注册 |

**关键做法**：MCP 在启动时探测，**没装的能力连工具都不注册**。

这样她不会"想用但用不了"，也不会因为工具太多而选错。

## 三、bridge 怎么进 SnowLuma

### 现状

```
SnowLuma（Electron/node.exe）  ── OneBot WS ──  bridge（独立 node 进程）
                    ↑ 两个进程，靠网络通信，配置各存一份
```

### 目标

```
SnowLuma（宿主）
  └─ 插件：xiaoyu-bridge
       · 能用 SnowLuma 的登录态、群列表、消息事件
       · 不用再连 WS，直接订阅事件
       · 配置合并进 SnowLuma 的设置界面
```

### 三步走（风险从低到高）

**第一步：配置单向共享（半天）**

```
bridge 启动时读 SnowLuma 的 onebot_*.json
  → 拿群/好友列表
  → 与自己的白名单比对，差异写日志提醒
```

先不动通信方式，只消除"两处维护"。

**第二步：插件形态（2~3 天）**

```
把 bridge 包成 SnowLuma 插件：
  · 插件入口 index.mjs
  · 订阅 message 事件（不再走 WS）
  · 出站仍用 SnowLuma 的发送 API
收益：延迟降低、少一个进程、登录态天然共享
风险：SnowLuma 更新可能破坏插件接口
```

**第三步（可选）：合并进主程序**

只有当 SnowLuma 提供稳定插件 API 时才做。**否则永久停在第二步。**

## 四、安装包设计

```
xiaoyu-setup.exe（约 40 MB）
  ├ 核心程序（SnowLuma 改造版 + 插件 + 管家）
  ├ 默认人格卡（用户可换）
  ├ 首启动向导：
  │   ① 扫码登录 QQ
  │   ② 填 API Key（LLM）
  │   ③ 选择人格（默认 / 空白 / 导入）
  │   ④ 可选：检测到本机有 GPT-SoVITS / ComfyUI → 一键接上
  └ 卸载时保留 state/（她的记忆不能删）
```

**可选模块**不进安装包，做成"模块中心"：

```
[ ] 声音（GPT-SoVITS，6 GB，需 GPU）
[ ] 画图（ComfyUI + SD1.5，12 GB，需 GPU）
[ ] 唱歌（RVC，3 GB，需她的音色模型）
```

点一下 → 后台下载 → 装到 `%LOCALAPPDATA%\xiaoyu\engines\`。

---

## 五、数据布局

```
%APPDATA%\xiaoyu\
  config.json          配置（API Key 加密存）
  persona.md           人格卡
  state\               她的记忆、日记、梦（永不删）
  engines\             可选模块（可删可重装）
  logs\
```

**核心升级不碰 state/**；卸载时问一句"要不要保留她的记忆"。

## 六、先做哪个

| 顺序 | 事项 | 为什么 |
|---|---|---|
| 1 | 能力探测 + 工具动态注册 | 模块化的地基，不做这个后面都白搭 |
| 2 | 管家外壳（状态面板 + 启停） | 用户能看见她在干嘛 |
| 3 | 配置单向共享 | 消除两处维护 |
| 4 | 安装包 | 有了 1~3 才有意义 |
| 5 | 插件形态 | 收益大但风险高，放最后 |

---

## 七、一句实话

**第 5 步（真正"逆向集成"）不建议现在做。**

原因：

```
SnowLuma 是别人的项目，会更新
它的插件接口没有公开承诺
一旦它改结构，整套要跟着改
```

**更稳的做法**：让 bridge 变成"能独立跑、也能被宿主拉起"的形态
（`--standalone` 走 WS，`--embedded` 收事件），这样两种都能用。
