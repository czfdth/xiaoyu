# 画册分步执行

通过 `qq_project_workflow` 在用户私聊维护页面任务。项目流程保存在现有 `state/projects.json` 的对应项目下，不迁移或认证旧作品，不修改既有进度。原进度为 8/20 时，新任务从第 9 页开始。

## 页面步骤

1. `start`：确定主题、构图与练习目标，创建一页任务；已有未完成页面时接续，不反复创建。
2. 调用 `qq_draw`，不传 key，只生成草稿而不发 QQ。`attach` 校验图片文件、哈希和时间，关联草稿并向模型返回真实图片供检查。
3. `review`：给出 accept/revise 与具体理由。可关联同会话、任务开始后的用户反馈，保留原话；模型自己的检查明确记为自检，不能冒充用户认可。
4. 需修改时保留旧版文件与要求，生成新版本后再次 attach/review。同一哈希不能冒充修改后的新版本。
5. `archive`：仅对通过检查且文件未变化的页面归档；页面、作品证据与进度在一个原子写入中保存，重复归档不会重复计数。
6. `deliver`：与归档分开，必须有当前会话实际发送过同一图片哈希的 QQ 回执。归档本身不等于交付，也不等于收件人已读。

启用页面流程后，旧 `qq_project_update` 不能绕过页面检查直接增加进度。每个版本的图片和检查记录仍保留，不删除或覆盖原图。

## 受阻和接续

`block` 保留原因与下一步；可以关联唤醒提示中的真实失败事件 ID，由服务器使用实际工具错误作为原因。普通失败至少等待半小时再 resume；连续三次失败或三版仍不通过时停止自动尝试，需用户在当前会话明确决定后再继续。用户确认只解除下一次尝试，不会把失败当成功。

页面任务在重启后保留；生活时段会看到下一步。主动检查在遵守未读、静默、连接和频率门槛的前提下，优先接续到期约定，其次推进已有页面，再考虑随机闲聊；同一页面半小时内不反复主动唤醒。新页面归档后有半小时自主冷却，用户明确要求时可以提前继续。

## 验证与边界

`npm run test:life` 共 32 项通过，包括 8 项页面流程测试，以及真实 bridge/MCP 接本地假 QQ 网关的集成测试。覆盖旧进度保留、版本与反馈、重启恢复、原子归档、重复登记、伪图与文件变化、失败重试、权限和交付哈希。

这是持久化执行状态机与工具接续机制，不是对模型审美、视觉判断和主动性稳定性的保证。真实生成仍取决于配置的绘图服务；本轮没有为测试生成付费图片或向真实 QQ 发送草稿，也没有虚增实际画册进度。
