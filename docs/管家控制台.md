# 小鱼管家 · 全栈控制台

> 2026-10-26 起，`gui/` 不再是那个 240 行的单文件面板，而是一个前后端分离的应用：
> **Vue 3 + Vite 前端** / **Fastify 后端** / 所有路径仍然只来自 `src/paths.js`。

---

## 一、为什么选这套（以及为什么不选别的）

先把候选在 GitHub 上的现状量了一遍（2026-10-26，GitHub API）：

| 仓库 | Stars | 最后提交 |
|---|---:|---|
| [vercel/next.js](https://github.com/vercel/next.js) | 143,292 | 2026-10-26 |
| [vitejs/vite](https://github.com/vitejs/vite) | 83,553 | 2026-10-26 |
| [nuxt/nuxt](https://github.com/nuxt/nuxt) | 60,991 | 2026-10-26 |
| [vuejs/core](https://github.com/vuejs/core) | 54,886 | 2026-10-26 |
| [fastify/fastify](https://github.com/fastify/fastify) | 37,301 | 2026-10-25 |
| [refinedev/refine](https://github.com/refinedev/refine) | 35,940 | 2026-09-10 |

结论：**Vue 3（视图）+ Vite（构建）+ Fastify（HTTP）**。

理由不是「star 多」，是**这个场景的形状**：

```
用户只有一个人（主人）
数据全在本机文件里（config.json / state/*.json(l) / roles/*.md）
要读任意目录、要 spawn PowerShell、要杀进程
离线也要能跑，不能依赖外部服务
```

- **Next.js / Nuxt**：SSR 对本地单用户面板没有收益；构建链更重（+150MB 依赖），
  而服务端要做的恰恰是 SSR 不擅长的「读本机任意文件、开子进程」。用不上，还多一层。
- **Refine**：面向数据库 CRUD 的后台框架，核心假设是「资源 + data provider + 标准 REST」。
  我们的数据是文件、动作是进程，套进去是逆着框架用。
- **Vue + Vite + Fastify**：三件都只做一件事，加起来 `106` 个包、`gui/node_modules` 约 40MB；
  本地起停毫秒级，构建 160ms，出问题能一眼看到底。

## 二、结构

```
gui/
  package.json          # 控制台自己的依赖（不污染根 package.json）
  server.mjs            # 入口：读 paths.js、ensureRuntime、监听 127.0.0.1:8765
  server/
    app.mjs             # Fastify 实例：/api 路由 + 静态 + SPA 回退
    data.mjs            # 读 config/state/roles/logs，写配置/人格卡（带备份）
    actions.mjs         # 三个白名单动作 → bin/*.ps1
    guard.mjs           # 本机来源校验、JSON 校验、QQ 号/名字规范化
  web/
    index.html
    vite.config.mjs     # root=web，产物写到 ../dist
    src/
      App.vue           # 侧栏 + 顶栏 + 路由出口 + Toast
      router.js         # 9 个页面
      api.js / store.js # fetch 封装 / 全局状态 / 轮询
      markdown.js       # 极简 Markdown（先转义再渲染）
      components/       # Card / Field / TagInput / Modal / StatusDot / Toast / Icon
      pages/            # Overview / Her / Memory / Persona / Tools / Life / Config / Logs / Setup
  dist/                 # 构建产物（随包发布，装完就能开）
```

数据流：

```
浏览器（Vue SPA）
   │  fetch /api/*      只走 127.0.0.1，写操作带 Origin + JSON
   ▼
Fastify
   ├── data.mjs ──► src/paths.js ──► config.json / state/ / roles/ / logs/
   │                └► detectEngines()（SnowLuma / GPT-SoVITS / ComfyUI / RVC / ffmpeg）
   └── actions.mjs ─► bin/start-all.ps1 · bin/xiaoyu.ps1 {stop|restart}
```

## 三、API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 存活 |
| GET | `/api/overview` | 端口、能力、引擎、她的状态、产出计数、配置警告（首屏一次拿全） |
| GET | `/api/config` | 配置（token 只回 `hasToken`） |
| PUT | `/api/config` | 合并写入 + 备份（白名单校验） |
| POST | `/api/setup` | 首次向导：ownerQQ / 白名单 / token / DSH 地址 |
| GET | `/api/her` | inner / body / mood / 当前人格卡 |
| GET | `/api/journal?day=` | 某天聊天记录（最多 300 条） |
| GET | `/api/journal/days` | 有记录的日期 |
| GET | `/api/journal/search?q=` | 跨最近 90 天聊天记录搜关键词（每条带 day / t / sender / text） |
| GET | `/api/memory/summary` | 日记/回忆录/梦/幻想/知识 的条数 |
| GET | `/api/memory/search?q=` | 跨全部记忆搜关键词（kind / id / title / snippet / at） |
| GET | `/api/memory/:kind` | `diary｜memoir｜dreams｜fantasies｜knowledge` 列表 |
| GET | `/api/memory/:kind/:id` | 读一条 |
| GET | `/api/roles` | 人格卡列表（标出当前） |
| GET | `/api/roles/:name` | 读一张 |
| PUT | `/api/roles/:name` | 保存（先备份，最多留 20 份） |
| GET | `/api/logs` | 可看的日志文件 |
| GET | `/api/logs/:name?lines=` | 尾部 N 行（10~2000） |
| GET | `/api/actions` | 允许的动作 |
| POST | `/api/actions/:name` | `start｜stop｜restart`，返回脚本输出 |
| GET | `/api/gateway` | SnowLuma 状态：装没装、版本、跑没跑、WebUI 端口、要不要扫码 |
| POST | `/api/gateway/start` | 用户显式确认（`confirm:true`）后打开已装的 launcher；`dryRun` 只回计划 |
| GET | `/api/tools` | 工具清单：向三个 MCP server 要 `tools/list`，按用途分组 + 使用次数/失败/最近一次（60 秒缓存，`?refresh=1` 强刷） |
| GET | `/api/life` | 出生日（`state/life.json`，首次从最早记录推断）、第几天、阶段、产出计数、长期项目、完整时间线 |
| GET | `/api/life/chronicles` | 已生成的年鉴列表（`state/chronicles/*.md`） |
| GET | `/api/life/chronicles/:name` | 读一份年鉴 |
| POST | `/api/life/chronicle` | 生成年鉴：`{days:100}` → 写 `state/chronicles/chronicle-<birth>-<天数>d.md`，返回 markdown |
| POST | `/api/tools/toggle` | 停用/启用单个工具：`{name, enabled}` → 写 `config.socialV2.disabledTools`（先备份） |

工具页的数据形状：`{ total, groups:[{id,label,tools:[{name,desc,tags}]}], disabled:[{flag,name}], capabilities, sources }`。
`disabled` 来自两处：`config.socialV2.tools` 里为 `false` 的开关，以及 `config.socialV2.disabledTools` 里逐个停用的工具名。
停用后桥接/MCP 会立即拒绝调用；重新启用要等 DSH 重启，工具才会重新出现在模型的列表里。

错误统一 `{ "error": "..." }` + 对应状态码。

## 四、安全边界

| 面 | 做法 |
|---|---|
| 监听 | 只绑 `127.0.0.1`，不开局域网 |
| 写操作 | 校验 `Host` 是本机 + `Origin`（若有）是本机 + `Content-Type: application/json` |
| 密钥 | 配置接口只回「有没有 token」，不回内容；前端留空 = 不修改 |
| 动作 | 三个固定脚本、固定参数；前端传不了命令 |
| 路径 | 人格卡名字过滤 `\\ / : * ? " < > |`、`.`、`..`；日志名走白名单 |
| 写入 | 配置/人格卡先 `copyFile` 备份再原子写（tmp + rename） |
| 前端 | Markdown 先整体转义再渲染；不用 `v-html` 接外部输入 |

## 五、开发与构建

```powershell
cd gui
npm install            # 首次（安装包里只带运行时依赖，构建工具要装回来）
npm run dev:api        # 后端 8765
npm run dev:web        # 前端 5173（/api 代理到 8765）
npm run build          # 产物 → gui/dist（随包发布）
```

> 体积：运行时依赖 `gui/node_modules` 约 **32 MB**（fastify + static 及其依赖）；
> 构建工具（vite / rolldown / lightningcss）另外约 34 MB，用 `npm install` 装回，不随包发。

在包根也可以用：

```powershell
npm run gui             # = node gui/server.mjs
npm run console:build   # = npm --prefix gui run build
npm run smoke           # 11 项自检，含「管家接口可用」（Fastify inject，不占端口）
```

> 改完前端必须 `npm run build`：安装包里跑的是 `gui/dist` 的构建产物，
> 不构建的话源码改了页面不会变。

## 六、接到现有数据上跑（迁移期）

代码根和数据根是分开的：

```
代码根  = src/ 的上一级（永远跟着文件走）
数据根  = XIAOYU_HOME || 代码根
          config.json  state/  logs/  roles/  images/  audio/
```

所以可以在**不动老仓库**的前提下，用新面板看老数据：

```powershell
$env:XIAOYU_HOME = 'C:\Users\best\Documents\deepseek-harness\default-workspace\qq-bridge'
node <这份包>\gui\server.mjs          # → http://127.0.0.1:8765
```

此时：

| 读的是 | 路径 |
|---|---|
| 配置 / 记忆 / 人格卡 / 图库 / 语音 | `XIAOYU_HOME` 下（老仓库） |
| 前端、脚本、MCP、preset | 包自己的目录 |

动作（启动/停止/重启）会先在数据根找 `bin/`，找不到再退回代码根，并用 `XIAOYU_HOME`
启动对应目录的 `src/bridge.js` —— 也就是说，它停的是**数据根那只** bridge。

确认没问题后再正式迁：把 `state/ config.json roles/` 拷进包，`scripts/setup-dsh.mjs`
重指向 MCP，重启 DSH。

> 2026-10-26 13:30 已用它替换了 `ai-her\gui` 的老面板：8765 现在跑的是这套，
> 数据仍指向 `qq-bridge`（零迁移）。过渡期的启动器是 `ai-her\打开新管家.bat`
> （它只是个带 `XIAOYU_HOME` 的 .bat，不在发布包里）。

## 七、已知取舍

- **没有登录**：本机单用户，登录只会变成「又一个要记的密码」；用回环绑定 + 同源校验替代。
- **没有数据库**：数据本来就是文件，引入 SQLite 只会多一份要同步的状态。
- **状态 15 秒轮询**：没有上 WebSocket——这个面板的实时性要求是「她有没有活着」，不是秒级行情。
- **动作是同步等待**：启动全部最长 240 秒，页面会显示「执行中」；够用，且比假进度条诚实。
