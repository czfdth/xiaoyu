# 记忆归属、约定履约与主动调度

本次修改不迁移或重写已有记忆。新数据与旧结构兼容，程序升级只同步明确列出的代码文件。

- 新记忆按会话分批提炼，附带人物 ID、会话、原话事件、消息 ID 与发生时间。模型不能把只有群友来源的条目保存成用户偏好。来源不明的旧身份、偏好、习惯、关系、纠正和经验仍原样保存，但不自动作为事实注入；旧经历和话题标未核实，身份称呼以当前角色与当事人纠正为准。原话检索要求会话令牌，不跨群检索。
- 处理成功的提炼批次与条目原子落盘；断网或格式错误不推进游标，重跑接续。保留旧条目及额外字段，不再从缺少日期和人物信息的活动日志猜测来源。
- `qq_commitments` 管理当前会话的具体约定：pending / in_progress / blocked / completed / cancelled。旧 promise 以 needs_review 展示，不修改原记忆；须关联原话或新确认的消息后才可执行。用户的承诺不会成为她的主动催办任务。
- 答应交付的事项需要成功发送的消息 ID 才能结案。图片/音频等作品同时要求作品文件，其 SHA256 必须匹配实际发送回执。说过“答应”那条消息不能作为完成证据。网关接受不等于收件人已读，也不证明作品质量。
- `qq_project_update` 一次登记一件实际作品，拒绝没有证据和重复哈希。原有 8/20 等历史进度保留，不追溯认证。
- 主动检查要求大脑、模式、QQ 通路就绪；缺失来信时间时保持安静。遵守静默、未读与频率门槛；到期且已核实、无未满足条件的自身约定优先。accepted 计数仅代表唤醒请求获接收，不等于发送或履约完成。生活时段可以在 QQ 离线而大脑就绪时继续独立活动。
- 新持久数据：`state/commitments.json`、`state/delivery-receipts.jsonl`；新记忆在原 `memory/long-term.json` 中追加来源和批次游标。旧文件不需要手工改格式。新文件随现有 state 备份策略保存。

测试：`npm run test:life`，19 项自动化测试（其中一项启动真实 bridge 与真实 MCP，用本地假网关覆盖完整交付和重启流程）。另运行原有配对测试与干净数据目录自检。

尚需真实运行观察：模型是否恰当识别明确承诺、是否主动调用约定工具、模型摘要内容是否忠实于原话。测试验证的是归属校验、证据、状态及调度机制，不代替这些行为层面的验证。修复不自动重跑旧聊天的模型提炼，也不因旧摘要未结案就对 QQ 发消息。
