# 语义检索（本地 bge-m3）

她“想起以前说过什么”原来是**关键词匹配**：说「薯片」能翻到，说「那个膨化零食」就翻不到。
这个模块把她的旧聊天、长期记忆、日记、知识、梦做成向量索引，用本地 `bge-m3` 按意思找原话。

| 项 | 值 |
|---|---|
| 模型 | `bge-m3`（1024 维，1.2 GB，不需要 GPU 满载） |
| 服务 | 本机 Ollama `http://127.0.0.1:11434` |
| 索引 | `state/semantic-index.json`（向量以 base64 存 Float32） |
| 速度 | 建索引约 **54 条/秒**；2860 条 28 秒；查询毫秒级 |
| 降级 | Ollama 没开 / 索引不存在 → 静默返回空，自动落回关键词 |

## 怎么用

```powershell
# 1) 确认 Ollama 在跑、有 bge-m3
ollama list

# 2) 建索引（增量，只算新增/改过的）
node scripts/build-semantic-index.mjs --days=90

#    --rebuild  全部重算（换模型时用）
#    --days=365 往前多少天的聊天，默认 90

# 3) 直接查
curl "http://127.0.0.1:3100/api/semantic/search?q=她卡住画不下去的时候&k=5" -H "x-console-token: <token>"
```

她会**自动用上**：`qq_recall` 先走关键词，命中不足 3 条时补语义检索（相似度 ≥ 0.45），
结果混在同一段里（语义命中的会标「按意思搜到 0.83」）。索引/ Ollama 不可用时只是少几条，不会报错。

## 实测（对真实数据）

索引 2858 条（journal 2794 / memory 33 / diary 20 / knowledge 9 / dream 2），15.3 MB。

| 查询 | 命中 |
|---|---|
| 她卡住画不下去的时候 | 0.859 「画图那边坏了，画不出来」· 0.819 「画册第九张又卡住了」· 0.799 「我又跟那张画较劲，还是出不来」 |
| 他半夜不睡觉 | 0.846 「今晚不睡」· 0.817 「不睡不睡」· 0.753 「你不也没睡吗？」 |
| 那个膨化零食 | 0.586 「那刚好吃饱了」· 0.574 「你想起来要吃什么糖了吗」 |

## 为什么不用本地模型替她说话

同一台机器（RTX 5060 Laptop **8 GB** 显存 + 31 GB 内存）实测：

| | qwen3:30b | qwen3.8:27b |
|---|---|---|
| prompt 处理 | 134 tok/s | 12.5 tok/s |
| 生成 | 5–11 tok/s | 5 tok/s |

她每一步 prompt 是 2~4.5 万 token，一个回合 3~6 步 —— 本地跑一条回复要等几分钟，**工具调用**也更容易错。
同一份记忆提炼任务（`extract-memory --dry`，同输入）：云端 27.7 秒 0 拒绝，本地 138 秒后**失败**
（返回散文而不是 JSON）。所以：**本地模型做检索，云端模型说话**。

## 维护

- 换了嵌入模型（比如换 `bge-large-zh`）→ `--rebuild`，否则新旧向量维度不一致
- 索引是纯派生物，随时可以删掉重建：`state/semantic-index.json`
- 想定时更新：`bin\tasks.ps1` 里加一条 `node scripts/build-semantic-index.mjs`（每天一次就够）
