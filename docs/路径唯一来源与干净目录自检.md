# 路径只有一个来源 · 改造记录与干净目录自检

> 2026-10-26 · 对应这五件事：
> ① 建 `src/paths.js` ② mcp/bridge 里写死的路径换成引用它 ③ start-all / status / gui 用同一套
> ④ 首次运行生成默认 config（含引擎路径探测）⑤ 在干净目录里测一遍

---

## 一、为什么要做

改造前，同一个事实（「包根在哪」「声音引擎在哪」）有四五份互相独立的写法：

```
src/bridge.js            C:/Users/best/Documents/.../qq-bridge   ← 写死一次（__C_ROOT）
src/mcp-snowluma-safe.js C:/Users/best/Desktop、C:/ai-voice/...   ← 又写死十几次
bin/start-all.ps1        $ROOT/$SL/$GS/$COMFY/$LOG               ← 再写死一遍
bin/status.mjs           C:/Users/.../qq-bridge, C:/Users/best/SnowLuma
gui/server.mjs           ROOT + AI（同上）
```

结果是：换一台机器、换一个盘、或者把包挪到别的目录，就会有一半功能**静默**读写老路径——
工具还在，但写进旧仓库、画到旧图库、拉起别人的引擎。而且没有任何报错。

## 二、现在长什么样

```
src/paths.js  ←—— 唯一路径来源（559 行，只依赖 Node 内置模块）
   ├─ 包根     APP_ROOT / SRC_DIR / DATA_DIR
   ├─ 目录     STATE_DIR LOGS_DIR ROLES_DIR IMAGES_DIR AUDIO_DIR SCRIPTS_DIR DSH_DIR
   │           PRESETS_DIR PLUGINS_DIR PUBLIC_DIR ASSETS_DIR ENGINES_DIR
   ├─ 常用文件 STATE_FILES.{sessions, mode, mood, inner, diaryDir, journalDir, ...}
   ├─ 端口     PORTS.{gateway, gatewayWs, tts, comfyui, bridge, gui}
   ├─ 用户目录 DESKTOP_DIR DOCUMENTS_DIR DOWNLOADS_DIR PC_ROOTS PC_NOTE_DIR
   └─ 引擎     detectEngines() → SnowLuma / GPT-SoVITS / ComfyUI / RVC / ffmpeg
                + ensureRuntime() → 建目录、首次运行生成 config.json
```

优先级：**环境变量 > `config.engines` > 常见安装位置 > 包内 `engines/`**。
探测只查候选目录（不扫全盘），找不到就返回空值，由上层优雅降级。

CLI（启动脚本就靠它拿同一份结果）：

```powershell
node src/paths.js            # 人看的摘要
node src/paths.js --json     # 给脚本解析
node src/paths.js --init     # 建目录 + 生成 config.json（幂等）
node src/paths.js --check    # 自检
```

  → 建 state/ logs/ state/{diary,journal,memoir,tmp}

## 六、两条边界

1. **SnowLuma 不代启动**（默认）。
   它是第三方专有组件，项目不变量 L6：只探测、不部署、不程序化启停。
   `start-all.ps1` 默认只提示你打开它；确认要它代劳时显式加 `-StartGateway`。

2. **升级不碰 `state/`**。
   `install.ps1` 覆盖程序文件时跳过 `state/`、`config.json`、`logs/`；
   卸载时也默认保留记忆，只有 `-Purge` 才删。
