# 运维：看门狗、迁移、回滚

> 装好之后日常会遇到的四件事：她掉线了怎么办、怎么从旧仓库搬过来、搬完怎么退回去、开机之后谁在跑。

## 一、看门狗（bridge / 面板掉了自动拉）

`bin\watchdog.ps1` 每 20 秒看一眼：

| 检查 | 掉了怎么办 |
|---|---|
| 大脑（3100） | `node src/bridge.js` 拉起来 |
| 管家面板（8765，仅 `-WithGui`） | `node gui/server.mjs` 拉起来 |
| 声音 GPT-SoVITS（9880，仅 `-WithEngines`） | 用 `config.engines.gptSovits` 的 python 重新起 `api_v2.py` |
| SnowLuma | **永远不管**（L6：只探测、不部署、不程序化启停） |
| ComfyUI | 不管（要吃显存，按需手动开） |

```powershell
bin\watchdog.ps1                 # 前台跑（Ctrl+C 停）
bin\watchdog.ps1 -WithGui        # 顺带看住面板
bin\watchdog.ps1 -WithEngines    # 顺带看住声音（9880）
bin\watchdog.ps1 -Once           # 只检查/修复一次
bin\watchdog.ps1 -CheckOnly      # 只报告，不动手
bin\watchdog.ps1 -IntervalSeconds 30
```

习惯用法：

- 开机自启已经带看门狗（`install.ps1` 写的 Run 项是 `start-all.ps1 -WithGui -Watchdog -NoGatewayWait -Fast -Quiet`，
  `-Fast` 让大脑/面板先起，声音和画图交给看门狗按需拉起，避免开机被引擎启动拖慢）
- 手动开：`bin\xiaoyu.ps1 watchdog`
- 日志：`logs\watchdog.log`（超过 1MB 自动滚动成 `.old`）
- 单实例：`state\watchdog.lock` 里是 PID；重复启动会直接退出
- **看门狗自己有人守**：计划任务 `xiaoyu-watchdog-guard` 每 5 分钟看一次
  `watchdog.lock` 的 PID，不在了就重新拉起（实测：杀掉 watchdog → guard 3 秒内拉回，PID 变了）

## 一·五、QQ 网关（SnowLuma）

**它不随这个程序分发。** SnowLuma 的 EULA 2.2 / 5.4 明确禁止把它并入第三方安装包、
或用自动化脚本部署；商业使用/公开分发还要作者书面授权（motricseven@foxmail.com）。
所以我们只做「检测 + 引导 + 你点了才打开」，不下载、不安装、不静默启动、不代扫码。

| 状态 | 你能做什么 |
|---|---|
| 已安装、没跑 | 面板「QQ 网关」卡片 →「启动 SnowLuma」；或 `bin\gateway.ps1 -Open` |
| 已安装、在跑 | 只看状态，什么都不用做 |
| 没安装 | 面板「怎么装网关」→ 打开官方 releases 页；装完把路径填进 `engines.snowluma.home` |

命令：

```powershell
bin\gateway.ps1          # 看状态（装在哪、版本、跑没跑、EULA 在哪）
bin\gateway.ps1 -Json    # 给脚本读
bin\gateway.ps1 -Open    # 打开已安装的 launcher.bat（登录仍要手动扫码）
```

- 面板按钮会先弹确认框，写明「只运行你已装好的程序，扫码要你自己完成」
- 如果 SnowLuma **开着但没登录**（WebUI 在 5099/5100 监听、OneBot 3000 没起），面板显示「已启动，待扫码登录」，
  按钮变成「打开登录页」，不会再开新实例（实测连点 4 次只会多出 4 个抢不到端口的短命进程）
- 启动记录写 `logs\gateway.log`
- 部署脚本第 2 步也会先问「现在打开 SnowLuma 吗？」，不会自己开

## 二、从旧 qq-bridge 迁过来

迁移脚本只搬**她的数据**，不碰代码：

```
config.json     → 覆盖（先备份）
state\          → 整目录复制（先备份）
roles\          → 整目录复制
```

```powershell
# 1) 先看计划（不动任何东西）
powershell -ExecutionPolicy Bypass -File bin\migrate.ps1 -From C:\path\to\qq-bridge -DryRun

# 2) 真迁
powershell -ExecutionPolicy Bypass -File bin\migrate.ps1 -From C:\path\to\qq-bridge
```

默认行为：

1. 停掉旧 bridge（读旧 `state\bridge.lock` 的 PID + 命令行匹配，避免两个实例抢消息）
2. 把新目录现有的 `state\` / `config.json` 备份成 `state.bak-<时间>` / `config.json.bak-<时间>`
3. 复制 config / state / roles
4. 跑 `scripts\setup-dsh.mjs --profile auto`，把 DSH 里的 MCP 指向新目录
5. 起新 bridge（8765 空闲时也起面板）
6. 检查 3100 / state / config，并写一份回滚说明

参数：

| 参数 | 作用 |
|---|---|
| `-DryRun` | 只打印计划 |
| `-NoStop` | 不停旧 bridge（会同时有两个实例，慎用） |
| `-NoDsh` | 不改 DSH 注册 |
| `-NoStart` | 迁完不启动 |
| `-Force` | 目标 state 非空也继续（会先备份） |

**没有目标 state 时不会覆盖**：发现 `state\` 里已有文件会直接拒绝，除非 `-Force`。

## 三、回滚

迁移脚本会在 `logs\migrate-<时间>.txt` 写一份回滚说明，大意是：

```powershell
# 1) 停新
powershell -File "<新目录>\bin\xiaoyu.ps1" stop
# 2) 起旧
cd "<旧目录>"; node src/bridge.js
# 3) 把 DSH 的工具指回旧目录
cd "<旧目录>"; node scripts/setup-dsh.mjs
# 4) 重启 DSH
```

旧目录全程**只读**（只读 config/state/roles），随时可以回去。

## 四、开机之后谁在跑

`install.ps1` 写的 Run 项：

```
start-all.ps1 -WithGui -Watchdog -NoGatewayWait -Quiet
```

顺序：

1. 探测并拉起**已装且没在跑**的引擎（GPT-SoVITS / ComfyUI，可选）
2. 起 bridge（SnowLuma 没开也不等，bridge 自己重连）
3. 起管家面板
4. 起看门狗（之后 bridge/面板掉了自动拉）

不启动 SnowLuma（L6：只探测、不部署、不程序化启停）。

## 五、常用排查

| 现象 | 看哪里 |
|---|---|
| 她突然不回 | 面板「概览」：大脑 DSH 是否在线、网关是否在线；`logs\watchdog.log` 有没有拉起记录 |
| 看门狗拉不起来 | `logs\bridge.err.log`；手动 `bin\xiaoyu.ps1 restart` 看报错 |
| 迁移后 DSH 里没工具 | 重启 DSH；再 `npm run dsh` 看注册状态 |
| 想确认跑的是哪份代码 | 面板左下角显示的数据目录；`node src/paths.js` 看代码目录/数据目录 |
| 某个定时行为没跑 | `bin\tasks.ps1 -List` 看状态；`logs\<log>` 看输出；任务历史 `Get-ScheduledTaskInfo -TaskName xiaoyu-*` |
| 想知道花费为什么高 | 面板「花费」：先看未命中，再看冷启动次数；按会话里「最近一步」最大的那条就是元凶 |
| 会话突然换新（她说"刚才聊到哪了"） | `state\bridge.log` 搜 `上下文轮换`：那是预算按 `rotatePromptTokens` 主动换的，正常 |
| 一回合被掐断 | `state\bridge.log` 搜 `上下文预算`：单回合步数到 `maxStepsPerTurn` 了 |

## 五·五、省 token 的两道刹车

会话历史只增不减，每步都要重发整段历史，所以省钱的杠杆不是「少说话」，而是**别让一条会话太长**。

| 键（`config.json` → `socialV2.context`） | 默认 | 超了会怎样 |
|---|---|---|
| `maxStepsPerTurn` | 30 | 单回合步数到线就 `stopSessionWork` 打断，日志 `⛔ 上下文预算：… 打断这一回合` |
| `rotatePromptTokens` | 80000 | 回合收尾后换新 DSH 会话，日志 `♻️ 上下文轮换：…` |
| `rotateMinTurns` | 5 | 会话至少跑这么多回合才允许轮换 |

```powershell
# 看预算在不在生效
Select-String -Path state\bridge.log -Pattern '上下文预算|上下文轮换' | Select-Object -Last 10
# 看每条会话现在多大（要控制台令牌）
$t = Get-Content state\console-token -Raw
(Invoke-WebRequest http://127.0.0.1:3100/api/status -Headers @{'x-console-token'=$t.Trim()} -UseBasicParsing).Content | ConvertFrom-Json | Select-Object -ExpandProperty contextBudget
```

注意：`scripts\reset-session.mjs` 是早先的定时重置（每 6 小时，但**只**覆盖 owner 私聊和 `group:1129441439`，
键是写死的）。预算这套是全量、按实际大小判定，并带「最近聊到哪」接力；两者可以共存，也可以只留预算。

## 六、定时行为（她的日子）

21 条计划任务由 `scripts\tasks.manifest.json` 定义，`bin\tasks.ps1` 负责落地：

```powershell
bin\tasks.ps1 -List       # 任务名/状态/wrapper/上次结果
bin\tasks.ps1 -Install    # 生成 wrapper + 注册/更新（保留原触发器）+ 启用
bin\tasks.ps1 -Remove     # 注销入口（日志和 state 保留）
```

| 类别 | 任务 | 做什么 | 日志 |
|---|---|---|---|
| 每天的仪式 | morning / night | 早上、睡前各一次唤醒（`ritual-wake`） | `ritual.log` |
| | dream | 04:00 做梦并写下来 | `dream-wake.log` |
| | memoir | 21:30 写回忆录 | `memoir.log` |
| | anniversary | 09:00 纪念日检查 | `anniversary.log` |
| | life-1/2/3 | 10:30 / 15:00 / 19:30 她自己过日子 | `life.log` |
| 记忆与整理 | memory | 04:40 把昨天对话蒸馏进长期记忆 | `memory-extract.log` |
| | world | 07:30 世界简报 | `world.log` |
| | cost | 23:00 账单 | `cost-report.log` |
| | tool-report | 23:05 工具使用报告 | `tool-usage.log` |

## 七、备份与恢复

```powershell
bin\backup.ps1                          # 打包 state/ roles/ config.json companion.json
bin\backup.ps1 -Out D:\xiaoyu-backups -KeepDays 30
bin\restore.ps1 -From <zip>             # 大脑在跑会拒绝（-Force 可强来，会先备份当前 state）
bin\restore.ps1 -From <zip> -Force -NoStart
```

- 备份放在 `<数据根>\backups\xiaoyu-<时间>.zip`（默认保留 14 天；state 里的 `tmp/` 不进包）
- 日志：`logs\backup.log`
- 恢复前会自动把当前 `state` 复制成 `state.before-restore-<时间>`，恢复失败还能回去
- 计划任务 `xiaoyu-backup` 每天 04:50 自动跑；关机错过的会在下次开机补跑（StartWhenAvailable）
- 实测：91 个 state 文件 + 5 张人格卡 + config + companion → 0.46 MB（压缩后）
