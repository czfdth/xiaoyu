# 一键部署与首次配对

> 目标：新用户从「下载了包」到「她能在 QQ 里回我」，**只需要点一次、扫一次、发六个数字**。

---

## 一、用户看到的三步

```
双击 一键部署.bat
   ↓
① 装好 → 自动打开 SnowLuma → 手机 QQ 扫码登录
   ↓
② 自动找到 DSH（大脑）的端口，注册工具
   ↓
③ 面板上出现 6 位数字（例：172906）
   ↓
④ 用自己的 QQ 私聊她，发这 6 位
   ↓
她回「配对成功」→ 完成
```

不需要打开 `config.json`，不需要抄 accessToken，也不需要知道 DSH 这次用的是哪个端口。

> 前置：本机要有 **DeepSeek Harness（DSH）** 并登录模型。它没有 DSH 也能对话，但"大脑"不在
> 就一条都不会回——面板会直接显示「大脑（DSH）没连上」。

---

## 二、脚本实际做了什么

`bin\deploy.ps1`（`一键部署.bat` 只是它的外壳）：

| 步骤 | 动作 | 失败时 |
|---|---|---|
| 1/6 | 检查 Node ≥ 22；调 `install.ps1 -Dest %LOCALAPPDATA%\xiaoyu` | 打开 nodejs.org，退出 |
| 2/6 | 找 SnowLuma；问一句后打开（**不代登录、不代安装**） | 打开官方 Releases 页，继续等网关 |
| 3/6 | `scripts\dsh-setup.mjs`：扫本机监听端口找到 DSH → 写 `dsh.baseUrl` → 没注册过就注册 MCP/preset | 提示先装 DSH，面板里可重试 |
| 4/6 | `scripts\first-run.mjs`：发现 SnowLuma 的 HTTP/WS 地址与 token → 写回；没有主人则生成配对码 | 面板里可重试 |
| 5/6 | `bin\xiaoyu.ps1 restart` 起大脑，`bin\xiaoyu.ps1 gui` 起面板并打开浏览器 | 8765 被占用时跳过并提示 |
| 6/6 | 打印配对码与面板地址 | — |

`scripts\dsh-setup.mjs` 单独跑也行：

```powershell
node scripts/dsh-setup.mjs            # 找 DSH + 注册（自动挑 profile）
node scripts/dsh-setup.mjs --json     # 给部署脚本读
node scripts/dsh-setup.mjs --no-register
```

**为什么需要它**：DSH 的 Web 端口是每次启动随机的（这台实测 63247，默认 3080 是错的），
而且桌面版的 profile 叫 `desktop` 而不是 `web`；以前 `setup-dsh.mjs` 默认写死 `web`，
会把工具注册到没人读的 profile 里。现在先扫 DSH 进程的监听端口，再自动挑profile
（已注册的 > 有 patch 的 > desktop/web）。

`scripts\first-run.mjs` 也可以单独跑：

```powershell
node scripts/first-run.mjs --wait 120        # 等人扫码，最多 120 秒
node scripts/first-run.mjs --pairing         # 重新生成配对码
node scripts/first-run.mjs --json            # 给脚本解析
```

它用 `src/snowluma/discover.js` 逐个试候选 token（配置里的、环境变量、SnowLuma 每个账号的
`onebot_<uin>.json`），谁能通过 `get_login_info` 就用谁，然后把 **HTTP token、WS token、两个端口**
一起写回。换 QQ 账号后重跑一次即可，不用手改。

## 三、配对码的安全边界

代码在 `src/pairing.js`，规则写死在那里：

| 约束 | 为什么 |
|---|---|
| 只在 `ownerQQ` 为空时接受 | 已经有主人就完全不看配对码，没有"偷偷换主人"的入口 |
| 只认私聊 | 群里发码无效（群消息不进入配对分支） |
| 6 位随机数字（10 万~99 万） | 足够短、好输入；配合次数限制够用 |
| 15 分钟过期 | 部署完不配就一直挂着，等于长期开后门 |
| 错 5 次作废 | 防暴力猜 |
| 成功立即删码 | 不可重放 |
| 码只存 `state/pairing.json`（0600），日志只记"成功/失败次数" | 不把凭据写进日志 |

配对成功后桥接会：

1. 把发送者写进 `config.json` 的 `ownerQQ`
2. 把发送者加进 `allow.private`
3. 回一句「配对成功」
4. 删掉 `state/pairing.json`

## 四、面板上的「一键配对」

`http://127.0.0.1:8765/setup` 顶部就是配对卡：

- 显示网关当前登录的号（`小鱼 · 你的号`）——确认扫的是哪个 QQ
- 大字配对码 + 倒计时 + 还能错几次
- 「换一个码 / 取消配对 / 手动刷新」
- 面板每 2.5 秒轮询 `GET /api/pairing`，配对成功会自动变成「已认主」

接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/pairing` | 状态（paired / active / code / 剩余时间 / 剩余次数） |
| POST | `/api/pairing` | 生成新码（已有主人则 400） |
| DELETE | `/api/pairing` | 取消配对 |

## 五、排错

| 现象 | 先看什么 |
|---|---|
| 部署脚本说找不到 SnowLuma | 它不在常见位置。装好后在 `config.json` 的 `engines.snowluma` 填目录，或设 `SNOWLUMA_HOME` |
| 一直"等网关上线" | SnowLuma 打开了但没登录；扫码后 3000 端口才会起来 |
| 面板显示「大脑（DSH）没连上」 | DSH 没开 / 没登录模型。打开 DSH 后点「首次设置 → 自动检测」，再点「用这个地址」 |
| DSH 在线但「工具未注册」 | 跑 `npm run dsh`（或 `node scripts/dsh-setup.mjs`），然后重启 DSH |
| 注册完还是没工具 | DSH 重启了吗？MCP / preset 只在启动时加载 |
| 网关在线但配对码发了没反应 | 面板里看倒计时/剩余次数；桥接日志 `state\bridge.log` 会有"配对码不匹配" |
| 提示"已经有主人" | `ownerQQ` 已填；要换人去「配置」清空 `ownerQQ` 再生成码 |
| 想完全手动 | 面板「首次设置」下面的手动表单，或直接改 `config.json` |

## 六、和"手动配置"的关系

一键部署不是另一套逻辑，它只是把原来的手工步骤串起来：

```
install.ps1              → 装文件
scripts/first-run.mjs    → paths.js --init + snowluma discover + config 写回 + 配对码
bin/xiaoyu.ps1 restart   → 起 bridge
bin/xiaoyu.ps1 gui       → 起面板
```

每一步都能单独跑；出问题时可以只重跑其中一步。
