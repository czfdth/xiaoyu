# 事件来源分层

事件来源现在区分为：

- `reported`：收到一条消息，只能证明当事人这样说过。
- `self_report`：她自己的叙述、日记、回忆、身体和内心状态，不是独立环境观察。
- `imagined`：梦、幻想和明确的想象，不可提炼为真实经历。
- `tool_observation`：bridge 记录的实际工具返回，只证明执行状态，不证明作品质量、消息已读或生成叙述的真实性。

新梦境、幻想、自省、日记等记录增加来源标签，不重写旧记录。聊天流水保留消息事实与内容类别，长期记忆提炼附带来源类别；若模型把有明确失败证据的工具原因改写成“手艺不好”等，存储层会以原工具记录替换该摘要。

`state/reality-events.jsonl` 记录有会话范围的工具结果（错误已由 bridge 脱敏）。同会话的最近相关工具结果进入唤醒提示；每日记忆提炼也能看到当天工具结果，不再只有事后的自我解释。

固定列表生成的虚构“日常麻烦”不再写入或注入，原 `hassle.json` 保留。旧日记、回忆录在提示中标为未核验叙述；模拟身体状态与真正生理测量区分。

实现边界：自然语言来源分类仍有启发式判断；标签与验证不能证明任意一句模型输出都真实。`reported` 不是已证实事实，不能当作独立外部证据。此轮未重新提炼历史记录，也未替她发送真实 QQ 测试消息。

验证：`npm run test:life` 共 24 项通过，包含 5 项新增分层测试及真实 bridge/MCP + 本地假 QQ 的集成测试。
