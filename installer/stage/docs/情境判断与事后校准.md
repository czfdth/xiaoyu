# 情境判断与事后校准

实际 QQ 来信是判断来源，保留会话、消息 ID、原话和时间。倾诉、收尾、简短回应、具体任务、求建议分别采用不同的长度、气泡及问题限额。判断暂定有效 30 分钟；不能据此宣称知道用户内心。转述、假设和超长文本不自动解释为当前需要。

bridge 与 MCP 在实际发送前共享 `state/situation.json` 的原子预留记录。文本、有正文的合成语音、未知正文的预录语音、图片表情和拍一拍都受同轮尺度限制；只有实际网关成功才标记成功。未知发送状态保守占用额度，审计失败不能触发重发。情境暂停不是工具故障，不切备用通道继续发送。

已回应且没有新来信时，回复检查不追加提问；主动联系未回应时，六小时内不重复主动联系同一轮。停止随机搜热点凑话题或编造生活经历。内部创作及练习可以继续。新来信重置主动标志，避免将直接回应误认成主动打扰。

用户明确纠正过多建议、反复追问、过度主动或机械套用偏好时，保存原话，关联最近实际且相符的发送动作，并暂时调整随后执行。没有匹配动作时只记明确边界。明确认可只证明用户认可这次回答；沉默、网关成功和模型自评均不构成满意度证据。

当前明确的详细解释、多条表达或画风/模板例外可以覆盖对应的旧表达偏好，仅在本次来信有效期内生效，不写回长期偏好。不得覆盖白名单、联系边界、人物要求和身份权限。反对机械套用偏好时暂不自动套用语气、详略或画风，禁止模板等明确限制仍保留。

验证：`tests/situation.test.mjs` 验证边界、并发、真实反馈校准及损坏数据保护；`tests/situation-integration.test.mjs` 用真实 bridge/MCP 接本地假 QQ 的 HTTP/WebSocket 协议，验证新来信到发送回执闭环，不向真实 QQ 发送测试消息。测试不证明模型在所有自然语言下都能正确判断，也不证明真实用户已认可。
