# 经历 → 反思 → 行为改变 → 再验证

已有的日记、梦、回忆与记忆提炼保留。新增 `state/experience-learning.json`，与人格卡、长期记忆分开，不把自述当成真实执行，也不把没有回复解释成用户讨厌。

## 如何形成与采用经验

1. **经历**：只接收程序实际执行的绘图尝试，以及 bridge 记录的结构化工具结果。保留来源、时间、结果；学习文件不保存原始聊天、错误中的密钥或图像字节。
2. **反思**：使用明确、有限的规则解释执行条件。主绘图服务连接失败/超时、CPU 备用成功，支持“近期先用适用的备用”。不从网络错误推断画技差；只失败而没有成功备用时不推断换路有效。
3. **改变**：绘图再次执行前，从磁盘读取相同服务与模型配置的有效经验。调用者明确选定适用的 `fallbackTemplate` 且允许备用时，顺序从主服务→备用改为备用→主服务。备用成功就不再重复碰已知不可用的主服务；备用失败仍给主服务恢复机会。
4. **验证**：每次采用有独立 ID，保留原计划、实际计划、依据、执行结果及结果证据 ID。生成成功仅表示工具生成，不等于质量合格、交付成功或用户满意。中断的 pending 采用记录不冒充成功。

规则有效期为最后一次主服务实际失败之后 30 分钟。反复用备用成功不会无限续期；到期重新探测主服务，配置变化不沿用旧规则。主服务恢复则关闭旧规则；备用也失败则将规则标记为需要复核。历史经历和反思保留。

发送、语音、草图、页面流程和约定也已接入执行层：失败后换既定备用、核对回执、暂停同条件重复写入，具体范围与时效见[工具执行调整](工具执行调整.md)。这些是有限任务的执行经验，不能据此宣称所有聊天习惯或人格都能自动学习。

## 查看、纠正与保护

- `qq_learning(key, token)`：只读查看当前会话的反思、证据与实际采用结果。
- `GET /api/socialV2/learning?key=...`：同样需要控制台认证或正确会话令牌；其他会话不能读取私有工具经验。绘图路由属于共用机器能力，不包含聊天内容。
- 操作台认证的 `POST /api/socialV2/learning` 接受 `{key, reflectionId, action:"disable"|"enable", reason}`。停用有独立授权记录；模型会话令牌只能读，不能自行启用或停用。重新启用不会延长过期时间，也不会把已撤回规则重新视为正确。
- 文件损坏或写入失败不会清空旧数据、重复绘图或冒称学会；提示说明状态不可读，执行恢复原计划。继续使用既有原子状态写入与部署备份。

## 验证边界

`tests/experience-learning.test.mjs` 验证经验去重、跨调用重读、执行顺序真实改变、结果回连、规则过期、配置变化、备用失效撤回、操作员停用、会话隔离、文件损坏保留。bridge/MCP 集成测试使用独立临时目录和假 QQ，验证只读工具与管理权限，不向真实 QQ 发消息。

本机同步后另用真实 MCP、真实本地绘图执行两轮验证：第一轮实际失败→备用成功形成经验，第二轮新 MCP 进程从磁盘读取经验、直接采用备用并记录结果。验证图片仅作为本机草稿，不推进画册或新增 QQ 交付。
