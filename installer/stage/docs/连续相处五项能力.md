# 连续相处的五项能力

这组能力通过 `qq_continuity` 和 `/api/socialV2/continuity` 使用，保存到独立的 `state/continuity.json`。原人格卡、长期记忆、日记、图片、音频和已归档页面不迁改。

| 能力 | 实现与实际影响 |
| --- | --- |
| 纠正与反馈 | 保存用户原话、消息 ID、时间、维度及适用范围；画面要求进入创作请求，明确不要模板时绘图与草图工具都不能用模板绕过 |
| 任务理解与验收 | 新页面开始时保存动机来源、原始请求和1到8项标准；检查必须逐项提供结果与理由。新增用户要求后旧检查不能直接用于归档 |
| 兴趣与持续练习 | 她可以自己选一个1到5步的小练习，记录动机、领域与标准。先提供实际新作品预览，再检查并推进；连续三次未达标暂停 |
| 连续自我认识 | 兴趣、偏好、长处、限制及做事方式关联练习或作品检查；保留前一版与变化原因。没有新经历不能每轮用同一依据重写自己 |
| 关系分寸与误会修复 | 安静、少连发、简短、不要某种称呼会影响最终发送；修复分为open、applied和confirmed，不能用反复道歉代替行为改变 |

## 用户纠正的边界

- `feedback` 需要真实用户 `sourceMessageId`。群友、她自己的话、梦、玩笑、假设、转述、否定意思不明的句子不能直接变成用户偏好。
- `session` 适用于当前交流，按原话时间12小时后过期；`task` 只适用于指定的实际任务，不能拿旧页面评价套给新页面；`conversation` 需要原话明确“以后、每次”等长期要求。
- 自动识别只覆盖明确的纠正或联系要求。不回复不表示讨厌；疑问句不自动设长期偏好；过长原话不截断后强行学习。
- 兼容的要求一起保留。替换用 `replacesId` 关联明确的新纠正；撤回用 `retract_feedback` 引用之后的用户原话。历史不删除。
- 用户要求暂不打扰而未指定时长时，默认30分钟，并记录这个默认值；明确长期不主动则持续有效，直到用户撤回。内部练习可以继续，主动联系被拦截；用户新来信仍可回应。
- 少连发会把统一发送合为一个完整气泡，并阻止同一来信一分钟内继续追加；静默期间只允许对每个新来信作有限回应。简短要求限制120字；纠正称呼后不允许继续以已拒绝的称呼开口。

## 新任务的验收

`qq_project_workflow start` 可提供 `criteria:["标准1","标准2"]`；未提供时以本页brief作为第一项。标准由代理拆解时标记为 `agent_plan`，不冒充用户已经认可。

`review` 的 `checks` 例如：

```json
[{"id":"c1","passed":true,"note":"实际查看后确认蓝色头发完整，未被画面边缘截断"}]
```

接收到的画面反馈有独立验收项 ID。每项都通过才允许归档；归档前再检查文件哈希及新增要求。自检仍是 `agent_self_review`，不是用户验收。历史已归档任务保持原样。

只画不发时，`qq_draw`/`qq_sketch` 使用 `contextKey`、当前会话 `token` 和可选 `taskId` 来读取对应反馈；提供交付 `key` 时两者必须相同，不能把私聊要求带到其他会话。

## 兴趣练习与认识自己

1. `practice_start`：主题、动机、领域（drawing/writing/communication）、步骤及每步criterion。没有用户来源时标记 `self_selected`，不能说成用户要求。至多一个active练习、三个未收尾计划。
2. `practice_attach`：关联这次新产生的作品。图片须在8MB内，文字草稿须在16KB内；MCP 返回图片或完整文字供实际检查。
3. `practice_review`：提供stepId、passed及具体note。文件被覆盖、假图片、旧作品、同一作品重复计入均拒绝。检查记录是 `agent_self_assessment`。
4. `practice_preview`：按reviewId重新查看旧作品，核对哈希，便于比较。
5. `practice_pause/resume/abandon`：保留理由与历史。三次失败后的恢复需要用户新决定；用户要求的练习不能由她自行取消。
6. `self_update`：提供field、value、reason与练习/检查的evidenceIds。能力自评必须有作品检查；更新保留previousId。它是有依据的自我陈述，不证明主观感受，也不等于客观能力测评。

主动检查在到期约定和现有页面之后接续兴趣练习，半小时内不会反复唤醒同一练习。刚完成后先休息；用户新要求可继续。实际行为采用与结果均保存，但不自动给用户发送练习进度。

## 误会修复

例如用户说“你理解错了，以后别叫我爸爸”：记录原话并建立open修复；实际发送时拒绝旧称呼，合适的新回应成功后记录applied；之后用户明确说“这样就好，你理解对了”，才能confirm_repair。仅仅“对了，明天……”这种换话题不算确认。

## 验证范围

单元测试检查来源、时间、范围、撤回、稳定自我版本、作品预览、逐项验收及主动联系边界。真实 bridge/MCP 接本机假 QQ 的集成测试覆盖模板拒绝、单气泡发送、停止追加、练习作品预览、自评、安静与纠正称呼、真实模拟回执后的修复确认及跨会话隔离。测试数据与假用户陈述只存在临时目录，不能写入她的真实记忆。

部署只同步白名单代码；正式运行目录只读验收并核对原有文件哈希。不会为了演示这些能力伪造用户偏好、种入兴趣或替用户确认误会已解决。
